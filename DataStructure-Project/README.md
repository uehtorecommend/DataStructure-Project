## 实验11：中国邮路问题的约束与回归测试

算法适用于**非负整数权的无向多重图**，允许不同权重的平行街道、零权街道和自环；不适用于有向图或负权图。图必须通过 `initGraph()`、`addStreet()` 构造：顶点数为 1～12，实际街道数最多 40（平行边、自环均分别计数），端点编号为 `0`～`n-1`，单条权重为 `0`～`INT_MAX`。初始化和添加成功返回 1；失败返回 0，添加失败不会部分修改图，调用者应检查返回值。初始化失败会使图处于无效状态（`n=0,m=0`）。

`edges[]` 保留全部街道以累加总长和度数（自环贡献两次度数）；邻接矩阵仅保存各对端点间的最小权重，且对角线保持 0，供 Floyd 求最短路径。随后枚举奇度顶点的完美匹配，求最小重复行走代价。每条街道必须能从所选邮局到达，未连接到街道的闲置顶点允许存在；邮局不可达任何待投递街道时返回 -1，包括“各分量都是欧拉图”的情况。没有街道时允许留在邮局，答案为 0。

`solveChinesePostman()` 保留原有打印功能，同时以 `long long` 返回最短闭合邮路长度，图规模/邮局无效或存在不可达街道时输出原因并返回 -1。路径、匹配代价和总长度均用 64 位整数；在上述容量及 32 位 `int` 权重范围内，闭合邮路长度不超过两倍街道总长（最多 `80 * INT_MAX`），远小于 `INF = LLONG_MAX / 4`。程序输出长度和奇点补边配对，**不生成逐条街道的实际行走序列**。Floyd 的时间复杂度为 O(n³)，奇点配对采用指数枚举，适用于本实验的小规模图。

在仓库根目录运行（需要 Python 3 和支持 C11 的编译器，无第三方 Python 依赖；可用 `CC` 指定编译器）：

```bash
python3 tests/test_chinese_postman.py
python3 tests/test_chinese_postman.py --sanitize
```

第二条命令需要 GCC/Clang 的 AddressSanitizer 和 UndefinedBehaviorSanitizer（推荐 Linux）。若受限运行环境不支持 LeakSanitizer，可用 `ASAN_OPTIONS=detect_leaks=0 python3 tests/test_chinese_postman.py --sanitize`，仍保留地址与未定义行为检查。GitHub Actions 会运行普通及 sanitizer 两组测试。

测试包含原一般图（33）、原欧拉图（14）、反例所有 24 种插入顺序（均为 25）、反向端点、同权平行边、零权边、自环、间接最短路、断开图、无街道、12 个奇点、40 条街道、`INT_MAX` 权重、非法输入及容量拒绝后的状态检查。另以固定种子 `20261104` 生成 300 个小图，用独立的 `(当前位置, 已覆盖街道集合)` 状态图 Dijkstra 核验最短闭合路线，不复用 Floyd 或奇点匹配；还检查打印出的配对是否完整、距离及合计是否正确。普通测试共核验 344 个邮路用例，并编译运行原有两个示例。

已复现并修复的反例为 `(0,1,1), (0,1,10), (0,2,3), (1,2,10)`：街道总长 24，奇点 0、1，最短补长 1，答案 25。原代码实际编译运行得到 34；修复后实际运行得到 25。将矩阵更新改回无条件覆盖时，回归测试会再次报告 `expected=25, actual=34`。
